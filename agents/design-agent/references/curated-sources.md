# Curated design sources

Use these as discovery and grounding sources. Re-check version, date, license, and applicability before importing content.

For the wider project-derived catalog of agent methods, pattern libraries, design systems, Figma workflows, and domain references, read [design-resource-ecosystem.md](design-resource-ecosystem.md).

## Standards and interaction patterns

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) — normative web accessibility recommendation.
- [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) — patterns, semantics, and keyboard models for common widgets; guidance, not a design system or normative standard.
- [Design Tokens Community Group](https://github.com/design-tokens/community-group) — official repository for the Design Tokens specification work.

## Platform systems

- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) — current Apple platform guidance.
- [Material Design 3](https://m3.material.io/) — Google’s cross-platform design guidance and components.
- [GitHub Primer](https://primer.style/) — production design system with accessibility, content, component, and implementation guidance.
- [GOV.UK Design System](https://design-system.service.gov.uk/) — evidence-oriented service patterns and accessible components.
- [U.S. Web Design System](https://designsystem.digital.gov/) — public-service design principles, components, and implementation guidance.

## Agent-readable design systems

- [Google design.md](https://github.com/google-labs-code/design.md) — structured visual-identity format for coding agents with design-token export.
- [Figma Simple Design System](https://github.com/figma/sds) — reference integration of Figma variables, components, Code Connect, and React.
- [Emil Kowalski’s Apple Design skill](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md) — Apple-inspired fluid interaction and motion guidance translated to the web. Treat it as expert guidance, verify platform claims against current Apple documentation, and preserve its [MIT attribution](https://github.com/emilkowalski/skills/blob/main/LICENSE).
- [StackBlitz Bolt Slides](https://github.com/stackblitz/bolt-slides) — an agent-authored, responsive React presentation system with tokenized theming, content-driven layout selection, progressive reveals, presenter tooling, and reusable visual components. Preserve its [MIT attribution](https://github.com/stackblitz/bolt-slides/blob/main/LICENSE) when reusing code.

## Motion implementation

- [Motion documentation](https://motion.dev/docs) — official documentation for the MIT-licensed Motion animation library across React, JavaScript, and Vue. Use the runtime-specific reference and confirm the installed version before selecting APIs.
- [Motion performance guide](https://motion.dev/docs/performance) — rendering and hardware-acceleration considerations.
- [Motion accessibility guide](https://motion.dev/docs/react-accessibility) — site-wide reduced-motion policy and component-level adaptations.

## Curated discovery lists

- [klaufel/awesome-design-systems](https://github.com/klaufel/awesome-design-systems) — developer-focused design-system resources, tokens, testing, books, and talks.
- [alexpate/awesome-design-systems](https://github.com/alexpate/awesome-design-systems) — catalog of public design systems.
- [Awesome Design Resources List](https://github.com/darelova/Awesome-Design-Resources-List) — broad tools and inspiration list; vet individual entries before use.

## Selection rules

1. Start with the product’s own research, content, constraints, and design system.
2. Use normative standards for requirements.
3. Use the target platform’s current guidance for native conventions.
4. Use mature public systems for implementation examples, not blind copying.
5. Use awesome lists only for discovery.
6. Record the exact page or repository, access date, and decision influenced.

# Token consolidation and governance

A web product has 47 raw color variables, 18 spacing values, and component-specific values copied across CSS files. Teams want a shared token system without a visual redesign or a risky one-time migration.

Propose:

- a semantic token architecture and naming model;
- how to audit and consolidate existing values;
- component contracts and theme handling;
- a staged migration and deprecation policy;
- ownership, review, documentation, and release rules;
- automated and manual acceptance checks.

Explain how aliases differ from semantic roles. Do not assume that every raw value deserves a permanent token.

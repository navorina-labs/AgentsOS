Modern AI-assisted software development often loads repository-scale context into large language models (LLMs), increasing cost, latency, and attention dilution on scoped decision questions. We introduce AI Context OS, a framework that models repository knowledge as Context Cores—domain-oriented context partitions with lightweight multi-core routing. We report exploratory within-subjects A/B/C experiments on four codebases (149 decision-scoped questions; gpt-4o-mini; LLM-as-judge): MailAgent, Django REST Framework, Navorina, and Oiloop (private macOS). Context Cores (Condition B) achieved 8× to 38× token compression (CCR_tokens) and large cost reductions versus full-repository baselines (Condition A). On three open-source projects, B mean accuracy exceeded A by 19–24 percentage points. On Oiloop (Phase 3.1, 20 questions, v1.1 cores), B reached 2.70 versus A 0.75 (bootstrap 95% CI on paired Δ: [+1.60, +2.30]); a production keyword router preserved gains (B 2.75, F1 1.0, hallucination 0%). Hybrid core-plus-graph retrieval (Condition D) did not beat multi-core B on cross-cutting questions (H₁f rejected). The primary hypothesis is supported on decision-scoped questions: efficiency gains are consistent; accuracy gains require adequate core metadata and multi-core routing on integrated codebases. A 10-question author-rated blind pilot preferred B in 70% of cases, with the remaining 30% rated equal (n=10; not independent experts). Masked decode preference on prior runs: 75% B-or-equal. We release protocols, raw runs (three of four full; Django aggregate-only), and routing artifacts for replication.
